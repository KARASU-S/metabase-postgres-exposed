## Описание уязвимости

При сканировании портов сервера `test.example.dev` обнаружено, что помимо
стандартных портов `22/80/443` из интернета доступны внутренние
инфраструктурные сервисы:

- **Порт 3000 — Metabase.** Внутренний экземпляр BI-системы, доступен
  напрямую по HTTP без проксирования через nginx и без HTTPS. Тот же
  экземпляр работает через `metabase.example.dev`. Прямой доступ
  позволяет обходить ограничения reverse-proxy, получать полную
  конфигурацию системы без авторизации через `/api/session/properties`
  и потенциально эксплуатировать уязвимости версии `v0.46.2`.

- **Порт 5432 — PostgreSQL.** СУБД принимает подключения из интернета.
  При подключении запрашивается пароль — значит, СУБД физически доступна
  извне. Даже при наличии парольной защиты сам факт открытого порта —
  грубое нарушение практик безопасности.

- **Порт 22 — SSH** с разрешённой парольной аутентификацией, а не только
  по ключу.

## Влияние на безопасность

1. **Metabase.** Прямой доступ к API в обход nginx открывает векторы
   для эксплуатации известных уязвимостей версии `v0.46.2` и перебора
   учётных данных. Утечка конфигурации через `/api/session/properties`
   упрощает дальнейшие атаки.

2. **PostgreSQL.** Критическая экспозиция СУБД в интернет: перебор
   паролей, эксплуатация уязвимостей PostgreSQL, атаки на протокол
   напрямую.

3. **Отсутствие сегментации.** Тестовый сервер с Yii-админкой не
   изолирован от продуктивных инфраструктурных сервисов. Компрометация
   тестового сервера означает компрометацию Metabase и PostgreSQL.

4. **SSH с парольной аутентификацией.** Расширяет поверхность для
   атак перебором по сравнению с аутентификацией только по ключу.

---

## Рекомендация

1. Закрыть порты `3000` и `5432` на внешнем firewall. Доступ — только
   через VPN / bastion.
2. PostgreSQL: `listen_addresses = 'localhost'`, `pg_hba.conf` — только
   внутренние подсети.
3. Metabase: за reverse-proxy с TLS и IP-allowlist, обновить до
   актуальной версии.
4. SSH: отключить `PasswordAuthentication`, только ключи + `fail2ban`.
5. Сегментировать тестовый и продуктивный контуры.
6. Регулярный скан периметра в cron с алертами.
